## Operating Doctrine

```text
The calendar is planned.

```

## Annual Programming Model

```text
Annual programming
-> seasonal thresholds
-> lunar / community rhythm
-> current invitation
```

The Shakti Portal should hold a stable public structure. The living programming rotates through that structure only after source capture, founder approval, asset readiness, and implementation review.

## Rhythm Record Fields

| Field | Description | Required for public use? |
|---|---|---|
| Year | Programming year | Yes |
| Sacred season / period | Navratri, retreat season, lunar period, or other founder-approved threshold | Yes |
| Primary container | Main offer or gathering | Yes |
| Purpose | Why this rhythm exists | Yes |
| Audience | Who it is for | Yes |
| Invitation window | When invitations open and close | Yes |
| Opening date | First public or participant-facing opening date | Yes |
| Delivery dates | Live and asynchronous delivery dates | Yes |
| Closing date | Final container date or review close | If applicable |
| Shakti Shala relationship | How this rhythm relates to Shala access or continuation | Yes |
| Content runway | Required public content sequence | Yes |
| Asset deadline | Date approved assets must be ready | Yes |
| Commerce deadline | Date payment/registration decisions must be ready | If commerce applies |
| Operations owner | Human owner for execution | Yes |
| Founder approval state | Draft, founder review, founder approved, superseded, deferred | Yes |
| Status | Idea, planning, build, preview, live, complete, archived | Yes |
| Notes | Context and future refinement | Optional |

## Idea / Future Rhythm Holding State

Use this state for spontaneous ideas, seasonal signals, or founder inspiration that should not immediately alter the public system.

Minimum fields:

- Idea name
- Source
- Date captured
- Founder relationship
- Possible season
- Possible audience
- Why it matters
- Known unknowns
- Required decisions
- Do not build before
- Review owner
