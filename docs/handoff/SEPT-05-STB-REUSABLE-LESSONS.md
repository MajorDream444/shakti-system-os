## Sept 05 Source-Strengthening Lesson

The Sept 5 amendment proved a reusable governance move:

```text
summary-supported claim
-> primary transcript arrives
-> admissible source window is enforced
-> direct claims upgrade
-> exploratory claims stay exploratory
-> runtime remains unchanged until a separate implementation gate
```

This should become an STB reusable skill because agents often overcorrect after receiving a transcript. The desired behavior is not "upgrade everything"; it is "upgrade only what the source directly supports."

## Founder Truth Before Software Pattern

Reusable pattern:

```text
FOUNDER EXPRESSION
-> SOURCE CAPTURE
-> RECONCILIATION
-> ACCEPTANCE BOUNDARY
-> IMPLEMENTATION CONSEQUENCE MAP
-> BUILD
-> HUMAN VERIFICATION
-> RELEASE
```

Reusable method:

- Capture founder speech before product changes.
- Reconcile new source against existing canonical truth.
- Separate accepted, held, exploratory, and asset-blocked decisions.
- Map implementation consequences before building.
- Let deterministic checks protect accepted truth where possible.

Client-specific material stays out of STB IP:

- doctrine
- sacred vocabulary
- founder-specific voice
- client imagery
- offer copy
- private data
- project IDs and integration IDs
